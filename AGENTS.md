# Repository guidance

## Project and scope

Sagaryet is a Tauri 2 desktop bridge from a deliberately limited OpenAI-compatible
text chat API to installed AI CLIs. The frontend is React 19, TypeScript and Vite;
the backend is Rust (edition 2024), Tokio and Axum. Use Bun and retain `bun.lock`
and `src-tauri/Cargo.lock`. This remains a development build; distinguish
implemented behavior, recorded verification and outstanding release gates.

Read `README.md` for supported API behavior and commands. `plan.md` and `docs/`
provide design and historical evidence; verify current behavior against code.
Do not describe historical live results as newly verified.

## Code map

- `src/App.tsx` and `src/App.css`: desktop setup, status, URLs and model list.
- `src-tauri/src/lib.rs`: Tauri IPC commands and app teardown.
- `src-tauri/src/server.rs`: HTTP, validation, authentication, request limits,
  queueing, streaming, cancellation and socket integration tests.
- `src-tauri/src/adapter.rs`: generation adapters and provider isolation.
- `src-tauri/src/catalog.rs` and `providers.rs`: discovery and login checks.
- `src-tauri/src/process.rs`: CLI lookup, bounded I/O and child process lifetime.
- `scripts/`: Python CLI checks, release version tooling and icon generation.
- `tests/`: Python unit tests, including release-tooling coverage.
- `.github/workflows/release.yml`: tag-triggered validation, installers and release publication.

## Local development and validation

Run commands from the repository root:

```sh
bun install --frozen-lockfile
bun run tauri dev
```

`bun run dev` serves only the frontend; Tauri IPC needs the desktop runtime.
`script/build_and_run.sh` builds and launches the macOS debug bundle, stopping
existing `sagaryet` processes first. It also supports `--debug`, `--logs`,
`--telemetry` and `--verify`.

Choose validation appropriate to the change. The standard checks are:

```sh
bun run build
bun run test
bun run version:check
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo clippy --manifest-path src-tauri/Cargo.toml --locked --all-targets -- -D warnings
```

`bun run test` runs Python unittest discovery followed by Rust tests. Default
Rust tests use synthetic adapters and real local HTTP sockets; they do not need
installed provider CLIs. For targeted work, run Python unittest discovery or a
filtered Cargo test. For packaging changes, also use `bun run tauri build --no-bundle`.
Documentation-only changes need link, command and diff review rather than a full build.

Installed discovery and LAN checks are ignored tests with separate environmental
requirements. Ignored generation tests consume provider quota; run them only
when live inference is within the requested task. Never run all ignored tests
indiscriminately. `bun run check:clis` checks installation/login without AI prompts.
Report the checks actually run and any relevant checks left unverified.

## Behavior and isolation constraints

- Keep the API text-only and strict about unsupported request fields. Preserve
  model and reasoning-effort validation, request/output limits and bounded queues.
- Preserve bearer authentication when a key is configured, Host validation and
  rejection of Origin-bearing requests. The desktop server binds to `0.0.0.0`
  and exposes unencrypted LAN access; keep UI and documentation accurate about it.
- Keep prompts, answers, access keys, provider credentials, private reasoning and
  raw CLI diagnostics out of persistent logs and client errors.
- Preserve ephemeral provider configuration, tool/MCP/hook/skill restrictions,
  bounded subprocess I/O and auth-copy cleanup. AGY is unsupported and must not be discovered or executed.
- Preserve cancellation and child process-tree cleanup on disconnect, Stop,
  timeout and app teardown. SSE failures must not emit a successful finish or
  `[DONE]` marker.
- CLI login status and model discovery do not prove successful generation.
  Account availability and model catalogs vary by installation.

## Changes and releases

Follow existing TypeScript and Rust conventions. Keep frontend IPC types aligned
with Rust responses and commands. Update the README when changing user-visible
behavior, setup, API compatibility or release workflows. Do not hand-edit build
outputs (`dist/`, `src-tauri/target/`) or the autogenerated Codex environment file.

Versions must agree across `package.json`, `src-tauri/tauri.conf.json`,
`src-tauri/Cargo.toml` and the `sagaryet` entry in `src-tauri/Cargo.lock`.
Use `bun run version:set -- VERSION` and `bun run version:check` for version edits.
Do not bump versions unless the task calls for it.

`bun run release VERSION` stages **all** pending changes, commits, tags and pushes
the branch and tag to `origin`. `--replace-tag` can replace a release tag.
Use these only for an explicitly requested release after reviewing pending changes.
`release:tag` also commits and creates a tag; it is not a validation command.
Only pushed `v*` tags trigger CI. The workflow publishes the draft after all
platform jobs succeed; branch pushes and pull requests do not run these checks.
